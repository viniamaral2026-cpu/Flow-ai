# Contributing / Desenvolvimento

## Antes de alterar
1. Leia o README e `docs/`.
2. Inspecione a estrutura real do repositório.
3. Localize implementação existente antes de criar arquivos.
4. Confirme contratos e dependências.
5. Planeje a menor mudança necessária.

## Fluxo obrigatório
LER → INSPECIONAR → LOCALIZAR → PLANEJAR → EXECUTAR → TESTAR → AUDITAR → DOCUMENTAR.

## Regras
- Não inventar endpoints, APIs, credenciais, classes ou resultados.
- Não duplicar funcionalidades.
- Não commitar secrets.
- Não alterar produção sem autorização.
- Manter testes e documentação sincronizados.
- Preservar compatibilidade entre clientes e backend.

## Pull Request
Descrever objetivo, arquivos alterados, impacto, testes executados, migrações e riscos.
